# Repository settings checklist (things only you can switch on)

These controls live in GitHub's and Vercel's settings, not in the repository, so nothing in CI can enforce or fully verify them. Each item gives the click path and a command or page that proves it. Commands assume `gh auth login` as the repository owner (`Aditya-tec/anomaly-zoo`). Spec references are to `spec.md` section 10.5 and 11.2.

**Order matters for one item.** Turn on *branch protection last* (item 8): once it is on, direct pushes to `main` (the way work has been done so far) are refused and every change needs a pull request with passing checks.

| # | Setting | Click path | How you verify it |
|---|---|---|---|
| 1 | **Private vulnerability reporting** (needed by `SECURITY.md`) | Repository → **Settings** → **Code security** (older UI: *Code security and analysis*) → **Private vulnerability reporting** → **Enable** | `gh api repos/Aditya-tec/anomaly-zoo/private-vulnerability-reporting` prints `{"enabled":true}`. Also: the **Security** tab shows a **Report a vulnerability** button when you are signed out or in a private window. |
| 2 | **Dependabot alerts** | **Settings** → **Code security** → **Dependabot alerts** → **Enable** (optionally also **Dependabot security updates**) | `gh api -i repos/Aditya-tec/anomaly-zoo/vulnerability-alerts` answers `HTTP/2 204` when enabled and `404` when not. |
| 3 | **Dependabot version updates** (configured by `.github/dependabot.yml`) | Nothing to switch on; the file is enough | **Insights** → **Dependency graph** → **Dependabot** tab lists gomod `/`, gomod `/conformance`, npm `/web` and github-actions `/` with a last-checked time. The first pull requests appear within a week. |
| 4 | **CodeQL** (configured by `.github/workflows/codeql.yml`) | **Do not enable "default setup".** Under **Settings** → **Code security** → **Code scanning** leave CodeQL on *Advanced* / *not configured by default setup*. Having both causes duplicate, conflicting runs. | `gh api repos/Aditya-tec/anomaly-zoo/code-scanning/default-setup --jq .state` prints `not-configured`. `gh run list --workflow codeql --limit 3` shows runs; the **Security** → **Code scanning** page shows results for Go and JavaScript/TypeScript. |
| 5 | **Secret scanning and push protection** | **Settings** → **Code security** → **Secret scanning** → **Enable**; then **Push protection** → **Enable** | `gh api repos/Aditya-tec/anomaly-zoo --jq .security_and_analysis` shows `secret_scanning` and `secret_scanning_push_protection` with `"status":"enabled"`. |
| 6 | **Workflow token defaults** (least privilege) | **Settings** → **Actions** → **General** → **Workflow permissions** → choose **Read repository contents and packages permissions**; leave **Allow GitHub Actions to create and approve pull requests** unchecked. Same page, **Fork pull request workflows**: require approval for all outside collaborators. | `gh api repos/Aditya-tec/anomaly-zoo/actions/permissions/workflow` prints `"default_workflow_permissions":"read"` and `"can_approve_pull_request_reviews":false`. |
| 7 | **Two-factor authentication** on GitHub and Vercel | GitHub: <https://github.com/settings/security> → **Two-factor authentication** → enabled (prefer a passkey or security key). Vercel: **Account Settings** → **Security** (or **Authentication**) → enable a passkey or an authenticator app. | GitHub: the same page shows "Enabled". Vercel: the same page lists the registered method. There is no API check for either; take a screenshot of each page for your records. |
| 8 | **Branch protection on `main`** (do this last) | **Settings** → **Branches** → **Add branch ruleset** (or **Add classic branch protection rule**) for `main`: require a pull request before merging; require status checks to pass: `go`, `conformance`, `web`, `e2e`, `security`, and `analyze (go)`, `analyze (javascript-typescript)` once CodeQL has run once; require branches to be up to date; require linear history; block force pushes; restrict deletions | `gh api repos/Aditya-tec/anomaly-zoo/branches/main/protection` (classic rule) or `gh api repos/Aditya-tec/anomaly-zoo/rulesets` (ruleset) shows those settings. Then try `git push origin main` from a clone: it must be rejected. Note: the `wasm` checks listed in spec 11.1 are inside the `go` job here, so there is no separate `wasm` check to require. |
| 9 | **Vercel project settings** (spec 11.2) | Vercel dashboard → the project → **Settings** → **General** → **Root Directory** `web`; **Settings** → **Environment Variables** → none; **Analytics** and **Speed Insights** → not enabled | The Environment Variables page is empty; the project's **Analytics** tab offers "Enable" (i.e. is off). After deploying, run `node web/scripts/check-deployed.mjs https://<your-host>`; it checks headers and CSP on every page. |
| 10 | **Actions allow-list** (optional hardening) | **Settings** → **Actions** → **General** → **Actions permissions** → **Allow {owner}, and select non-{owner}, actions** → allow `actions/*` and `github/codeql-action/*` | `gh api repos/Aditya-tec/anomaly-zoo/actions/permissions` shows `"allowed_actions":"selected"`. Every `uses:` in the repository is already pinned to a commit SHA, which `node scripts/verify-hardening.mjs` checks. |

## What the repository itself already checks

`node scripts/verify-hardening.mjs` (run in CI by the `security` job) verifies, from the files: pinned Actions, `permissions: {}`, no `pull_request_target`, no secrets, no script injection, `.npmrc`, dependency counts and exact versions, the Dependabot and CodeQL configuration, the policy files, the response headers in `web/vercel.json`, and the absence of HTML sinks and third-party URLs in the web source. It prints one line per control. It cannot see anything in the tables above.
